# CMS Editability Migration Notes

## Overview
This document describes the changes made to improve CMS editability for the Jazzfőváros website, along with any manual migration steps required for the editor.

**Last updated:** Second hardening pass (May 11, 2026)

---

## Changes Summary

### 1. Accommodation Page (Szállás)

**Problem:** Small note block was hardcoded in static files (`src/content/hu.ts` and `src/content/en.ts`) and not editable in Sanity CMS.

**Solution:** Added `introNoteHu` and `introNoteEn` fields to the Page schema for the `szallas` and `terkep` slugs.

**Files Changed:**
- `src/sanity/schemaTypes/documents/page.ts` - Added introNoteHu/introNoteEn fields
- `src/sanity/types.ts` - Added introNoteHu/introNoteEn to SanityPage type
- `src/sanity/lib/queries.ts` - Added introNoteHu/introNoteEn to getActivePageBySlugQuery
- `src/sanity/lib/content.ts` - Added introNote to getPageContentBySlug return type and logic
- `src/app/szallas/page.tsx` - Changed from `accommodation.note` to `page.introNote`
- `src/app/terkep/page.tsx` - Added introNote rendering

**Manual Migration Steps:**
1. Open Sanity Studio
2. Navigate to the "Page" document with slug `szallas`
3. Copy the note text from the static file:
   - HU: "Fesztiválszálloda: az árak reggelivel értendők, az idegenforgalmi adó nem tartalmazzák (400 Ft/fő/éj, 18 éves kortól). Foglalj minél hamarabb — a fesztivál idején korlátozott a szabad szobák száma."
   - EN: "Festival hotel rates include breakfast. Tourist tax not included (HUF 400/person/night, ages 18+). Book early — rooms are limited during the festival."
4. Paste into the "Kiemelt megjegyzés – HU" field
5. Repeat for English version if needed
6. Publish the changes

**Acceptance Test:**
- Clear the Hungarian note field → no Hungarian note block appears
- Clear the English note field → no English note block appears
- No duplicate blocks appear unless both fields are intentionally filled

### 4. Performer Image Cropping

**Problem:** Group photos were cropped with `object-cover`, cutting off people.

**Solution:**
- Changed card aspect ratio from `aspect-[4/3]` to `aspect-[3/4]` (taller, better for group photos)
- Added `objectPosition: "top center"` to prioritize top of image
- Changed detail page to use `object-cover` on mobile and `object-contain` on desktop

**Files Changed:**
- `src/components/lineup/LineupGrid.tsx` - Updated aspect ratio and object-fit settings

**Manual Migration Steps:** None required. The fix is automatic.

**Acceptance Test:**
- Group photos show more of the image
- Detail page shows complete image on desktop
- Images remain visually consistent

### 5. Program Hide/Unpublish

**Solution:** The `isActive` field already existed in the programItem schema and was already being used in the query. No changes needed.

### 6. Band Members (Zenekari tagok)

**Problem:** Band member lists were hardcoded in `src/app/lineup/page.tsx` and not editable in Sanity.

**Solution:** Added structured `members` array field to the performer schema with support for name, role, instrument, country, and standalone performer flag.

**Files Changed:**
- `src/sanity/schemaTypes/documents/performer.ts` - Added members array field
- `src/sanity/types.ts` - Added members to SanityPerformer type
- `src/sanity/lib/queries.ts` - Added members to PERFORMER_PROJECTION
- `src/sanity/lib/content.ts` - Updated getPerformersWithFallback to convert CMS members to lineup format
- `src/lib/types.ts` - Added lineup and programs fields to Artist type
- `src/app/lineup/page.tsx` - Updated to prefer CMS members over hardcoded

**Manual Migration Steps:**
1. Open Sanity Studio
2. Navigate to each Performer document that needs band members
3. Use the new "Zenekari tagok / Közreműködők" field to add members
4. For each member, fill in:
   - Név (required)
   - Szerep (HU/EN) - optional, e.g., "zenekarvezető", "vendégművész"
   - Hangszer (HU/EN) - optional, e.g., "zongora", "trombita"
   - Országkód - optional, e.g., "H", "USA", "S"
   - Ország neve (HU/EN) - optional
   - Megjelenik önálló fellépőként? - default false, only enable if you want this member to appear as a separate performer card
5. Publish the changes

**Hardcoded Data to Remove:**
After migration, the hardcoded `performerDetailsHu` object in `src/app/lineup/page.tsx` can be removed. However, it's kept as a fallback for now.

**Acceptance Test:**
- Editor can create a band
- Editor can add band members
- Band members show on the performer detail page under "Közreműködők"
- Band members do not show as standalone performer cards unless showAsStandalonePerformer=true

**Files Changed:**

## Portable Text Limitations (Current State)

### Overview
The current implementation uses simple text fields and a `displayMode` field for basic formatting control. Full Portable Text (rich text editing with bold, italic, links, etc.) is not implemented.

### Current Formatting Capabilities

**displayMode field (available on campScheduleBlocks):**
- `"list"`: Renders content as bullet points with orange dots
- `"paragraphs"`: Renders content as plain paragraphs without bullets

**What displayMode CAN do:**
- Switch between bullet list and paragraph formatting
- Provide basic structure control for long-form content

**What displayMode CANNOT do:**
- Bold, italic, underline text
- Add hyperlinks
- Add headings within content blocks
- Add lists within paragraphs
- Add blockquotes
- Add code blocks
- Add any rich text formatting

### Fields Without Rich Text Support

The following fields are plain text and do NOT support any formatting:
- All `descriptionHu/En` fields (venue, accommodation, performers)
- All `shortDescriptionHu/En` fields (performers, programs)
- All `bioHu/En` fields (performers)
- All `titleHu/En`, `subtitleHu/En` fields (pages, venue, accommodation)
- All `bulletsHu/En` fields (camp schedule blocks)
- All `body` fields (pages - currently plain text, not Portable Text)

### Recommended Portable Text Implementation (Future)

**Priority 1 (High Impact):**
- Convert `page.body` to Portable Text - this is the main long-form content field
- Convert `performer.bioHu/En` to Portable Text - performer bios benefit from links and formatting

**Priority 2 (Medium Impact):**
- Convert `campScheduleBlocks.bulletsHu/En` to Portable Text - camp program descriptions
- Convert `programItem.descriptionHu/En` to Portable Text - program descriptions

**Priority 3 (Low Impact):**
- Convert shortDescription fields to Portable Text - typically short, less need for formatting
- Convert venue/accommodation descriptions to Portable Text - typically short, informational

### Implementation Notes

When implementing Portable Text:
1. Update field types from `type: "text"` to `type: "array"` with Portable Text definition
2. Update GROQ queries to fetch the new Portable Text fields
3. Update rendering components to use `@portabletext/react` or custom Portable Text renderer
4. Ensure existing content is migrated (plain text can be auto-converted to Portable Text)
5. Update EDITOR_GUIDE.md with Portable Text editing instructions

### Current Workaround

For now, editors can:
- Use the `displayMode` field to control list vs paragraph formatting
- Create multiple separate blocks for different content sections
- Use line breaks within text fields for basic separation
- Note: Any links or formatting must be added as separate HTML or will be rendered as plain text
